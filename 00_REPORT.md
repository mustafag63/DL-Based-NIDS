# IDS Internship Project — Consolidated Report

**What this project is:** an intrusion detection system (IDS) built from
a lab network. A Zeek sensor captures `conn.log` flow records for a web
server (192.168.10.1) while benign traffic is generated by a Selenium
browser bot + Locust load generator (both from 192.168.10.3) and attack
traffic — nmap port scans, Apache Bench (HTTP flood), and Slowloris —
is launched from a Windows "Dell" attacker machine (192.168.10.2). The
end goal is an autoencoder-based anomaly detector trained only on
benign flows, evaluated on held-out benign + attack flows.

This report is a standalone, chronological narrative of the whole
project — Phase 1 (data collection) → Phase 2 (feature extraction +
leakage-free split) → Phase 3 (autoencoder training + ablation). All
numbers below are taken directly from the project's `context.md`
working log and the actual result files copied into this folder;
nothing is estimated or invented.

**Folder map for this consolidation** (see bottom of file for full
structure/sizes):
- `01_phase1_data_collection/window_meta_summaries/` — per-window capture metadata
- `02_phase2_feature_extraction/` — feature extraction script + final feature matrix
- `03_phase3_splits/` — train/val/test split files + split stability results
- `04_phase3_models/` — trained autoencoder models (.keras)
- `05_phase3_results/` — evaluation metrics (JSON)

## Phase 1 — Data Collection Pipeline

8 capture "windows" were collected, each combining benign and attack
traffic simultaneously against the lab web server, with target attack
percentages ranging 0–22% (`window_01_0pct` … `window_08_22pct`).
Ground truth: `is_attack` label derived from source IP
(192.168.10.2 = attacker); `actual_attack_pct` recorded per window in
`window_meta.json` (copied into `01_phase1_data_collection/window_meta_summaries/`).

**Bugs found and fixed during collection:**

- **window_01 Zeek-restart bug (9 July):** the first `window_01_0pct`
  capture produced 329,913 flows, 96.8% in Zeek's `OTH` connection
  state — traced to a mid-capture Zeek process restart. Fixed by
  adding continuous PID monitoring plus a post-hoc `reporter.log`
  check; window_01 was re-captured cleanly on 10 July (567 raw / 547
  lab-filtered flows, 0% OTH, `actual_attack_pct=0.0`).
- **NIC checksum-offloading bug (window_02–08, 9 July):** with checksum
  offloading enabled on the capture NIC, Zeek could barely see
  response-side traffic — window_02's conn_state distribution was 61%
  `SH` + 38% `S0`, and `resp_bytes` was undercounted by roughly 235×.
  Fixed by disabling checksum offloading and re-capturing all 7
  windows on 10 July (evening); window_02's conn_state distribution
  corrected to 97.2% `SF`.
- Both broken capture sets were archived on Mac and Pi as methodology
  evidence (`*_BROKEN_20260709/`, `*_BROKEN_checksum_20260709/`), then
  **deleted with explicit user approval** on 11 July (~119MB reclaimed
  total across both machines, verified via `du -sh` before deletion and
  `ls` after — this consolidation does not touch that decision, the
  broken data no longer exists anywhere).

**Result:** 8/8 healthy windows, consistent capture methodology.

contamination level.

## Phase 2 — Feature Extraction, EDA, and Leakage-Free Split

Script: `02_phase2_feature_extraction/faz2_feature_extraction.py`
(final version — this single script now does feature extraction *and*
the train/val/test split, see below).

### Feature set

From Zeek `conn.log`, flows are filtered to lab IPs
(192.168.10.1/.2/.3), labeled `is_attack`, and enriched with 3 derived
features: `bytes_per_sec = orig_bytes/duration`,
`pkts_per_sec = orig_pkts/duration` (0 for `duration==0` flows —
verified 0 such flows exist in the corrected dataset), and
`byte_ratio = orig_bytes/(resp_bytes+1)`.

**Final numeric feature set (8 columns, StandardScaler):** `duration,
orig_bytes, resp_bytes, orig_pkts, resp_pkts, bytes_per_sec,
pkts_per_sec, byte_ratio`.

- `missed_bytes` dropped: constant 0 across all 8 windows.
- `orig_ip_bytes` / `resp_ip_bytes` dropped (EDA finding): correlated
  r=0.996 / r=0.99996 with `orig_bytes` / `resp_bytes` — redundant.

**Categorical feature set (OneHotEncoder, global fit, 10 columns):**
`proto` (tcp/udp), `service` (dns/http/none/ssh), `conn_state`
(REJ/RSTO/S1/SF).

**Final feature matrix** (`features_all_windows.csv` /
`.parquet` in `02_phase2_feature_extraction/`): 36,705 rows × 22
columns.

### EDA highlights

- Class balance: 32,835 benign / 3,870 attack (10.54% attack).
- **Naive baseline:** the single rule **"conn_state != SF → predict
  attack"** achieves **precision=0.9908, recall=0.6656, F1=0.7963**
  on the full dataset — used throughout as the reference point for
  Phase 3 model evaluation.
- `byte_ratio`: benign median=0.060, attack median=0.032 (weak
  separation in the median); benign mean=0.081, attack mean=70.25
  (strong separation in the mean, driven by heavy-tailed attack
  outliers). |z|>3 outlier rate: benign 3.64% vs attack **33.44%**.
  (An earlier note claiming "benign median 834 vs attack median 11"
  was found to be computed on checksum-bug-contaminated data and is
  invalid — the numbers above are the corrected ones.)
- `pkts_per_sec` shows a similar pattern: benign |z|>3 rate 2.89% vs
  attack **32.56%** — both features flagged as strong expected anomaly
  signals for the autoencoder.

### Near-duplicate / leakage risk (critical finding)

Attack flows were grouped by a signature
(`window_id|proto|service|conn_state|round(duration,1)|round(orig_bytes,-1)`).
**The top-5 signatures cover 72–97% of attack flows per window**
(worst case: window_02, 96.8% coverage from just 6 unique signatures) —
the same attack tool is re-run with the same parameters repeatedly.
Naive random flow-level splitting would leak near-identical flows
across train/val/test.

**Attack-tool attribution** (via `attack_log.csv` timestamp overlap):
portscan (nmap), apache_bench, and slowloris are all scaled by the
**same single parameter `N`** tied to `target_pct` (e.g. `nmap -p 1-N`,
`ab -n N`, `slowloris -s N`). In flow-feature space, **apache_bench and
slowloris are nearly indistinguishable** (both ~100% `RSTO` conn_state,
~28-29s duration, byte_ratio≈210); only **portscan is clearly
distinct** (short duration, high pkts/sec, mixed conn_state, wide port
range). The model is effectively learning ~2 distinguishable clusters,
not 3 separate attack "concepts."

### Signature-grouped train/val/test split

Built with `sklearn.GroupShuffleSplit`, grouped by signature_id so no
signature appears in more than one split (verified via assertion, zero
overlap found):

- `window_01_0pct` (pure benign, statistically distinct from the other
  7 windows — higher mean duration/bytes, plausibly due to its small
  sample size of 547 flows) is carved out separately: 50% folded into
  train, 50% saved as a standalone **`window01_shift_test`** set
  (`03_phase3_splits/window01_shift_test.csv`) for a distribution-shift
  generalization check.
- Remaining benign (windows 02–08): 70% train / 15% val / 15% test.
  **Train is 100% benign** (anomaly-detection standard — the
  autoencoder must never see attack data during fitting).
- Attack flows: never in train, split 50/50 between val (threshold
  calibration) / test (final evaluation), also signature-grouped.

**Multi-seed stability check** (seeds 0–4, same split logic — see
`03_phase3_splits/multi_seed_variance_results.txt`): train_n varied
22,476–23,526 (std=467), test_attack_pct varied 24.5%–31.7%
(std=2.68 points) — a non-trivial variance, flagged as a "split
instability" risk. Phase 3 results are reported as mean±std over
multiple *model-training* seeds to partially compensate (though the
underlying data split itself is fixed to one chosen seed, see below).

**Official split seed: 1** (lowest per-window train-fraction imbalance
across the 5 candidates).

| set | n_flows | benign | attack | unique_signatures |
|---|---|---|---|---|
| train | 23,274 (63.4%) | 23,274 | 0 | 13,513 |
| val | 6,576 (17.9%) | 4,609 | 1,967 | 2,943 |
| test | 6,581 (17.9%) | 4,678 | 1,903 | 2,943 |
| window01_shift_test | 274 (0.7%) | 274 | 0 | 205 |

**Known caveat:** window_08's attack flows are unevenly split between
val (961) and test (177) — a ~5.4:1 ratio, a byproduct of signature
grouping (full window×split breakdown in
`03_phase3_splits/multi_seed_variance_results.txt`). Window_07 shows
the opposite skew. Not corrected — inherent to signature-grouped
splitting and present across all candidate seeds; flagged for
per-window metric reporting in future analysis.

### Scaler leakage fix (critical)

**Bug:** the original pipeline fit `StandardScaler` on all 8 windows'
benign data *before* running the train/val/test split (which lived in
a separate script) — the scaler's statistics were influenced by benign
flows that would end up in val/test. Classic leakage.

**Fix:** feature extraction and splitting were merged into one
pipeline (now just `faz2_feature_extraction.py`) where the split
happens *first*, and `StandardScaler` is fit **only on the train
split** (100% benign by construction); `transform()` is then applied
to all rows. `OneHotEncoder` remains a global fit (deliberate —
categorical vocabulary must span both benign and attack states).

Verified: with the fix, the `train` split's scaled columns now have
**exact mean=0.0, std=1.0** (e.g. `duration_scaled`: old train
mean=-0.0113 → new mean=0.0000). The original leakage's magnitude was
small but real (e.g. `byte_ratio_scaled` train mean was 0.0224 under
the old, leaky fit).

## Phase 3 — Autoencoder Architecture, Training, and Ablation

**Official result:** the numbers in this section (18/14 flow-level
columns, `04_phase3_models/` + `05_phase3_results/`, F1=0.862, aggregate
recall=80%) are the project's current, adopted result. A follow-up
experiment that added 4 IP-based rolling time-window features raised
aggregate recall to 100% but was **not adopted** — the gain was found to
be partly a lab-specific artifact rather than a clean behavioral signal.
It is archived, with full rejection rationale, at
[`experiments/v2_ip_aggregation_rejected/README.md`](experiments/v2_ip_aggregation_rejected/README.md).

### Environment

TensorFlow 2.21.0 on Mac (Apple Silicon, arm64), CPU-only
(`tensorflow-metal` 1.2.0 was incompatible with this TensorFlow
version — `dlopen` failure loading `libmetal_plugin.dylib` — removed;
CPU was fast enough for this scale: ~23K training rows, 3-hidden-layer
model, 2.5–6.7s per training run).

### Architecture

```
Input(N) → Dense(16, relu, L2=1e-4) → Dropout(0.15)
         → Dense(8, relu, L2=1e-4, bottleneck) → Dropout(0.15)
         → Dense(16, relu, L2=1e-4) → Dense(N, linear)
```
Loss: MSE. Optimizer: Adam. Batch size: 128. Max epochs: 200 with
`EarlyStopping(monitor=val_loss, patience=12, restore_best_weights=True)`.
`val_loss` is computed **only on benign val flows** — attack flows in
val are never used for loss monitoring, only for threshold calibration
downstream. Trained from scratch for 5 weight-initialization seeds
(0–4) per feature-set variant (10 models total, in
`04_phase3_models/`).

Two feature-set variants (ablation design):
- **full_features**: 18 columns (8 scaled numeric + 10 one-hot
  categorical, including conn_state).
- **no_conn_state**: 14 columns (conn_state's 4 one-hot columns
  removed) — tests whether the model depends on the same signal the
  naive baseline exploits.

### Threshold calibration methods

For each trained model, reconstruction error (per-sample MSE) is
computed on val and test. Two thresholds are derived from val:
1. **pctl95**: 95th percentile of the benign-only val error
   distribution.
2. **youden**: the ROC-optimal threshold (max of TPR−FPR, Youden's J)
   computed from val (benign+attack).

Test-set precision/recall/F1/accuracy are computed at both thresholds,
plus test AUC (threshold-independent).

### Results (5-seed mean ± std)

Full numbers in `05_phase3_results/{full_features,no_conn_state}_summary.json`
and `ablation_comparison.json`.

| Metric | full_features (18 cols) | no_conn_state (14 cols) | Naive baseline |
|---|---|---|---|
| **Test AUC** | 0.9463 ± 0.0104 | 0.9341 ± 0.0126 | — |
| Train time (s) | 4.50 ± 1.45 | 3.89 ± 1.03 | — |
| Epochs run | 41.0 ± 15.6 | 34.4 ± 10.5 | — |
| **pctl95** precision | 0.9353 ± 0.0181 | 0.9460 ± 0.0255 | 0.9908 |
| **pctl95** recall | 0.8002 ± 0.0023 | 0.7956 ± 0.0000 | 0.6656 |
| **pctl95** F1 | **0.8624 ± 0.0068** | **0.8641 ± 0.0107** | 0.7963 |
| pctl95 accuracy | 0.9261 ± 0.0044 | 0.9276 ± 0.0067 | — |
| youden precision | 0.5951 ± 0.0441 | 0.6590 ± 0.1728 | — |
| youden recall | 0.9995 ± 0.0011 | 0.9554 ± 0.0805 | — |
| youden F1 | 0.7451 ± 0.0351 | 0.7591 ± 0.0680 | — |

**Autoencoder vs. naive baseline:** the autoencoder (full_features,
pctl95 threshold) achieves **F1=0.8624, beating the naive baseline's
0.7963** — the gain comes almost entirely from recall (0.800 vs
0.666), while precision is slightly below the naive rule's (0.935 vs
0.991, expected since the naive rule almost never false-alarms on a
single highly-discriminative column). The Youden threshold trades
precision for near-perfect recall (~1.0) — a very different operating
point, less useful as a production default than pctl95.

**Ablation conclusion:** the full-vs-ablated gap is **small** — AUC
delta +0.0122 (within the std of both), pctl95 F1 delta only -0.0017
(no_conn_state is *not* meaningfully worse). **The model does not
depend on conn_state as a shortcut** — it retains almost the same
discriminative power without it, meaning other features (notably
`pkts_per_sec` and `byte_ratio`, flagged in the Phase 2 EDA as strong
anomaly signals) carry real, independent signal.

  infeasible to attribute reliably at flow level — not included in the
  feature set (granularity mismatch: ~4.45 Locust requests per Zeek
  flow due to HTTP keep-alive, and no port/session correlation exists
  between the two log sources). The `window01_shift_test` set was
  built but not yet evaluated against the trained models — a natural
  next step to test generalization to a distribution-shifted benign
  sample.

## Phase 3 — VAE variant (`phase3_vae/`)

A second Phase 3 model added alongside the Dense autoencoder above: a
Variational Autoencoder trained on `window_10_0pct`, a dedicated clean-benign
capture window, and evaluated against Dense's existing labeled val/test split
(`phase3_dense/03_phase3_splits/`) as a labeled evaluation set — this is a
health-check, not an architecture comparison against Dense.

Final architecture: `18 -> Dense(16, relu) -> Dropout(0.1) -> Dense(8, relu) ->
[z_mean(10), z_log_var(10)]` encoder, symmetric decoder, latent_dim=10,
beta=0.25 (selected after comparing beta=1.0/0.5/0.25 and sigmoid KL-annealing
to address partial posterior collapse - beta=0.25 tripled the number of active
latent dimensions, 1/10 to 3/10, with no AUC cost).

**Health-check result:** test AUC=0.9372, F1=0.8413 (pctl95 threshold).

See `phase3_vae/phase3_vae_autoencoder.ipynb` for the full latent-dimension
sweep, collapse diagnostics, and loss curves, and `phase3_vae/README.md` for
a caveat on loading the saved encoder/decoder `.keras` files standalone.

## Phase 3 — VAE contamination sweep (`phase3_vae/05_contamination_sweep/`) — 2026-07-16

Extension of the VAE health-check above: same final architecture
(latent=10, beta=0.25) retrained at 0/1/2/4/8/12% train-set contamination
levels (5 weight-init seeds each, 30 models total), all evaluated on one
fixed held-out test set (727 flows, 654 benign + 73 attack, ~10.04%
contamination) — adapting the leakage-free protocol from Nkashama et al.
(2024), *"Deep Learning for Network Anomaly Detection under Data
Contamination"*.

Attack pool built from `window_02`–`window_08` (`window_09` was never
captured in the raw backup — only `window_01`–`08` and `window_10_0pct`
exist). Benign pool from `window_10_0pct`, 3-way split (train
pool/threshold-val/test, 70/15/15) so the threshold-calibration and test
benign flows never touch training. Scaler/encoder reused Dense's existing
read-only refit pattern (`prepare_window10.py`), never refit on this
experiment's own data. All flow-level disjointness (benign train/val/test,
attack pool/test) verified via in-code assertions.

**Result:** PR-AUC drops fairly sharply from 0.718 (0%) to ~0.66-0.67 (4%)
as contamination rises, consistent with Nkashama's core finding that an
unsupervised reconstruction-error model starts treating injected attack
flows as "normal." Confirmed the 8% level's raw per-seed PR-AUCs
(0.675/0.675/0.679/0.699/**0.478**) contain one genuine outlier
(`seed=1`) dragging its mean (0.641) and std (0.092, 4-20x every other
level's) far from the other four seeds' tight band. Diagnosed the
outlier by checking active latent dimensions (the same collapse
diagnostic used in the original beta sweep): `seed=1` has 9/10 active
dims — not collapsed — while `seed=4` at the same level has only 3/10
active dims yet a normal PR-AUC (0.699), so posterior collapse does not
explain the failure; it reads as ordinary seed-to-seed training
variance. `results_summary.csv` now reports median and trimmed mean
(drop min+max of 5 seeds) alongside mean±std for exactly this reason —
by either robust statistic, 8% (median 0.675) sits close to 12% (median
0.680), and the corrected picture from 4% onward is a noisy plateau
(~0.66-0.685) rather than a monotonic decline or a real 12% reversal.
Benign FPR stayed roughly stable (~3.8-4.6%) across levels because each
model's threshold is calibrated against its own held-out validation
error distribution. Full writeup, per-seed/summary tables, and the
contamination curve: [`phase3_vae/05_contamination_sweep/README.md`](phase3_vae/05_contamination_sweep/README.md).

Also surfaced (and worked around) a pre-existing Keras issue: reloading
`encoder.keras`/`decoder.keras` in a fresh process raises `NameError: name
'tf' is not defined` from the log-var-clipping `Lambda` layer — Keras's
`Lambda.from_config` → `func_load` reconstructs the closure using its own
`python_utils` module's globals, which never imports `tensorflow`. This
reproduces identically on the existing `vae_encoder_final.keras`/
`vae_decoder_final.keras` (independent of this sweep), so the "does not
run standalone" caveat in `phase3_vae/README.md` is deeper than documented
there. Workaround (`evaluate_contamination_sweep.py`): inject `tf` into
`keras.src.utils.python_utils`'s namespace before calling
`load_model(..., safe_mode=False)` — no saved file is modified.
